## 比赛规则

在正式做题之前，强烈建议先阅读一遍以下比赛规则。

1. 不得作弊。比赛为个人赛，任何多人合作完成题目的行为都将被认为作弊。我们将进行代码查重，希望大家诚信参赛。
2. 不得使用恶意代码注入等方式对评测与 OJ 进行攻击。本比赛不是 CTF，不考察任何形式的攻击。如果我们发现任何攻击行为，将取消参赛成绩。
3. 不得打表。超算比赛要求保证优化后源码的正确性与普适性。如果我们发现你的代码中基于给出的示例算例打表，将取消参赛成绩。同时我们在评测时会适当修改示例算例中的部分数据。
4. 使用计时计算性能的题目均给出了明确的计时阶段，不得通过使用编程语言的异步等特性将原处于计时段的计算过程移动到计时段外以减小运行时间。
5. 可以使用搜索引擎与 AI 辅助答题，具体支持与资源见「Agent 辅助答题」。
6. 请不要在登录节点上运行并行编译或并行计算等高负载程序。交我算平台设有相应检测，如因在登录节点上进行运行高负载程序导致封号后果自负。
7. 比赛分发的交我算账号仅用于参加本次比赛，请勿滥用交我算平台计算资源，一经发现，立即封号。
8. 比赛结束后组委会将进行 Code Review，如发现违规行为将进行处罚，排行榜名次可能发生变动。请确保你上传的代码是开发的原始代码，严禁上传编译后/混淆后的代码阻碍 Code Review。恶意阻碍、拒不配合 Code Review 者将被取消参赛成绩。

## 集群使用指导

详见 [HPC 入门指南 - 计算机网络 - 登录交我算集群](https://xflops.sjtu.edu.cn/hpc-start-guide/network/login-HPC/)。

CPU 集群设置 `kp_run` 与 `kp_interact` 两个队列供选手使用。

### kp_run

该队列用于运行所需核心数较多的(>8核心)的试题，队列最长运行时间为2h，允许申请的最大的核心数量为128核心，仅允许使用1个节点。

### kp_interact

该队列用于使用 VSCode 连接计算节点开发以及交互式操作测试核心数较少的(<=8核心)题目，队列最长运行时间为8h，允许申请的最大核心数量为8核心，仅允许使用1个节点。

推荐使用 kp_interact 队列进行 VSCode 连接，用于交互式开发与代码测试。对于需要较多核心数运行的题目，编写 slurm 脚本并使用 sbatch 提交到 kp_run 队列运行。

> 再次提醒，不要在登录节点上进行 VSCode 连接做代码开发，语法解析器可能导致高负载占用。交我算平台设有登录节点运行程序负载检测，如因在登录节点上进行运行高负载程序导致封号后果自负。

NPU 集群设置 `contest-slice` 与 `contest-full` 队列供选手使用。

### contest-slice

该队列最长运行时间为 2h，单任务**必须**申请 12 核 CPU + 1 卡 NPU，仅允许使用 1 个节点。由于资源有限，每位选手 **每 4h 最多使用 3h**，超过限制的任务将被强制终止。**该限制可能依据资源使用情况进行调整**。

### contest-full

该队列最长运行时间为 1h，单任务**必须**申请 192 核 CPU + 8 卡 NPU，仅允许使用 1 个节点。由于资源有限，每位选手 **每 3h 最多使用 2h**，超过限制的任务将被强制终止。**该限制可能依据资源使用情况进行调整**。

该队列仅在 `LLM Serving` 题目中 `Stage1` 达到满分后解锁使用权限。

### HelloHPC CLI

为方便选手在本地自测，我们开发了命令行工具 `hellohpc`。选手可在赛题目录下（应包含 `problem.yaml` 文件）使用 `hellohpc test` 命令进行本地测试，使用 `hellohpc pack` 命令生成提交包。

此工具已预安装在集群，位置如下：

- CPU 集群：`/vault/public/xflops/bin/hellohpc`
- NPU 集群：`/nfs/bin/hellohpc`

选手可将对应目录添加到 `PATH` 环境变量中以更方便的使用。

**注意**：本地自测分数可能与 OJ 评测分数不同，请以 OJ 评测分数为准。

### 打榜题

打榜题是比赛中的一种特殊题型，该类题目不设置固定的满分线，而是以所有选手有效提交中性能最优者的性能指标作为满分线，其它选手的成绩按一定公式插值计算。为了避免比赛初期成绩浮动过大，打榜题会额外设置一个“满分控制线”，实际使用的满分线为“满分控制线”与“性能最优者指标”中较优者。

**注意**：对于打榜题，本地自测分数不为 0 仅代表你的提交合法且通过了正确性检验，具体分数与 OJ 分数没有直接关系，请以 OJ 评测分数为准。

### 提交方式

大部分题目的提交界面直接展示文本框，选手仅需要把对应文件名的文件内容复制进去即可。少部分题目要求提交压缩包，选手可在题目目录下使用 `hellohpc pack` 命令生成提交包。

### 测评环境说明

请注意，所有题目的评测均在容器内进行，因此环境与集群默认环境可能存在一定差异。请确保你的代码不依赖特定版本的编译器/系统库。一部分题目允许选手手动按需 `module load` 所需模块，这些模块的版本严格保持与集群默认环境一致。
